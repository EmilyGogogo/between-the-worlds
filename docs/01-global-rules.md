# 全局规则

版本：0.4-review · 2026-11-01。来源：创作者 2026-10-31 的 MUST／TUNABLE／DEFERRED 规则提案，以及 2026-11-01 的玩法修订（见 [09](09-decisions.md) D-006～D-012）；初始化协作与文档审计见 D-014、D-015；人开场见 D-017；魂穿尺度档与视点抬升见 D-021（取代 D-017 中“任意身体可见岛即可成为岛”的部分）。

**本稿已按创作者最新指示改写，团队共同确认仍待填写。规则等级、评审状态、实现状态是三个独立字段：写成 MUST 不等于已经实现。**

## 分类与修改权限

| 等级 | 含义 | 变更方式 |
| --- | --- | --- |
| MUST | 本次作品必须满足的行为或边界 | 团队共同确认后修改，在 09 记录决定、原因、影响和确认人；不在代码中静默改写 |
| TUNABLE | 方向确定，具体数值通过试玩调整 | 在允许范围内改 `data/` 中的唯一数值源，记录旧值→新值与试玩结果；超出范围或改变能力属于规则变更 |
| DEFERRED | 本次 Demo 不投入实现或验收 | 登记进 [DEFERRED](../DEFERRED.md)；原型里已有的实验代码也不能出现在提交版 |

## 目标与范围

| 编号 | 规则 | 等级 |
| --- | --- | --- |
| G-01 | 核心体验是“成为不同存在后，看见、听见和行动的方式随之改变”；每个类别至少一项可验证的独特能力或感知差异，同类别的不同种类可以主要在外形、动作、节奏和栖息地上区分 | MUST |
| G-02 | 3–5 分钟内可以完成一次“人开场 → 自由切换身体 → 岛 → 逐级回到小尺度”的尺度往返；之后可以继续漫游，没有强制计时或结束画面 | MUST |
| G-03 | 玩家不死亡、不失败、不被任务链驱赶；技术错误不转化为玩家惩罚 | MUST |
| G-04 | 首版世界是一座可细致探索的主岛，加上周边群岛与海；可魂穿类别限定为草、树、人、狗、鸟、鱼、岩石、岛屿，具体种类以 `data/entities.json` 为准 | MUST |
| G-05 | 星球、太阳、房屋、花、同类同行、复杂生态、运行时生成玩法不进入首版 | DEFERRED |
| G-06 | 从点击开始 30 秒内，无讲解的新玩家理解“看着目标按 R 魂穿” | MUST |
| G-07 | 核心时刻：从人开始探索；沿尺度档逐级长大（例如人 → 树 → 巨岩），或飞到足够高处，在视野中辨认出岛并看到岛的涟漪时，可以按 R 成为它，看到群岛与海；再逐级回到小尺度时，世界状态连续。看不见岛的小身体（如草）不能一步成为岛（D-021） | MUST |
| G-08 | 框架可扩展：在已有类别内新增种类（如新的鸟、鱼、狗）只改数据（可用 `project/new_species.py` 生成），不改玩法代码；新种类声明 `scaleTier` 即由 P-12 推导魂穿关系，不手写关系矩阵；新增尺度档在 `entities.json` 的 `scaleTiers` 登记；新增类别（如房屋）在 `categories` 登记并附 09 的决策编号，需要新的占位外形时注册一个占位生成器；扩展方法见 [数据与扩展指南](../data/README.md) | MUST |

当前基线 11 种（D-022）：细叶草；阔叶树、松树；海岸岩石、海岸巨岩（岩丘）；岛屿；人；狗；海鸥；银斧鱼、七彩神仙鱼（均在山湖，D-027 取代 D-022 的银色小鱼与蝴蝶鱼）。每种有多个个体。逐种说明见 [04 实体目录](04-entity-catalog.md)。

## 操作

| 编号 | 规则 | 等级 |
| --- | --- | --- |
| I-01 | 人用前后键相对镜头前后移动，左右键原地转向并带动镜头；其他身体用 WASD 或方向键相对镜头移动；鼠标环视；Shift 加速；R 魂穿；Esc 暂停／继续（D-025） | MUST |
| I-02 | 不设跳跃、上升、下降按键，Space 与 Ctrl 不绑定、不提示；鸟和鱼沿镜头俯仰方向上下移动，人入水时在水面游泳，其余地面状态贴地（D-026） | MUST |
| I-03 | E 保留、不绑定、不在任何提示中出现 | MUST |
| I-04 | 键位、暂停菜单、提示、`data/input-map.json` 与代码一致；进入前解释指针隐藏及 Esc 释放；按实际锁定状态提示鼠标环视或左键拖动，锁定失败仍可移动；失焦自动暂停并说明原因 | MUST |

## 身体与感知

| 编号 | 规则 | 等级 |
| --- | --- | --- |
| B-01 | 每种身体独立配置类别、尺度层、尺度档、移动方式、独特能力、感知档案、魂穿关系、碰撞、镜头与资产槽 | MUST |
| B-02 | 速度、加速度、转向、加速倍率、观察与魂穿距离、镜头数值按身体调优 | TUNABLE |
| B-03 | 能力通过空间、动作和声音自然表达；不用文字、能力等级或任务锁解释路线 | MUST |
| B-04 | 每种动物都有可辨认的感知档案，视觉（色彩、对比、清晰距离、视野宽度）与听觉（频段、听距、声源方向）都有差异；狗看到黑白世界；人的档案只是参照，不代表“真实的世界” | MUST |
| B-05 | 感知参数（饱和度、对比、雾距、FOV、滤波频率、听距、增益）与切换淡化时长 | TUNABLE |

## 目标选择与魂穿

| 编号 | 规则 | 等级 |
| --- | --- | --- |
| P-01 | 仅当前视野内、范围内、未完全遮挡、关系允许且可进入的实体具有候选资格 | MUST |
| P-02 | 部分可见且可辨认就可以选中；完全遮挡必须取消；透明材质不能自动当作可见 | MUST |
| P-03 | 同时只有一个主目标显示涟漪反馈 | MUST |
| P-04 | 先过滤合法条件，以最小镜头夹角形成容差组；组内较小、较具体的目标优先于其承载整体，再比较距离，距离在容差内时比较设计优先级，最后以实例 ID 打破平局。低优先级因素不得反超明显更对准的目标 | MUST |
| P-05 | 没有合法目标时按 R 保持原状；目标消失、失效或完全遮挡时取消选中 | MUST |
| P-06 | 按 R 时重新验证目标；过渡期间忽略重复 R、移动和加速 | MUST |
| P-07 | 魂穿是连续的镜头与声音过渡，旧身体留在原处；不瞬间切场景，不同时控制两个身体 | MUST |
| P-08 | 目标准备失败或落点失效时恢复原身体、镜头与世界状态，不显示失败提示 | MUST |
| P-09 | 旧身体持续存在；满足当前关系、可见性和其他合法条件时可以再次进入，也可选择其他合法目标，无需解锁；不提供绕过尺度关系的即时返回 | MUST |
| P-10 | 过渡默认 2.4 秒，可在 1.5–3 秒内调整；镜头路径按体型、遮挡和防眩晕调整 | TUNABLE |
| P-11 | 选中稳定时间、角度与距离容差、提示强度、音效淡入时间可调，但不能保留已非法的目标 | TUNABLE |
| P-12 | 尺度关系（D-021）：每种身体声明一个尺度档（`scaleTier`，当前 S1 近地、S2 人身、S3 林冠、S4 地貌、S5 群岛）；只能进入本档与相邻档的存在，相邻只按有成员的档计算。因此草不能直接进入树、巨岩或岛，人不能直接进入巨岩或岛，岛向下只到巨岩。关系由档位推导，不手写矩阵；个别例外写在该种类的 `relationOverrides` 并注明 09 的决策编号。关系允许不等于可以选中，仍须满足 P-01～P-05 | MUST |
| P-13 | 承载自己的更大整体（脚下的岛、所站的岩丘）在关系允许时，以可辨认的局部作为目标，例如岸线、地表、山体；只有看向大地、没有更对准或角度近似的合法子代目标时，它才成为主目标 | MUST |
| P-14 | 魂穿过渡中视觉与听觉感知档案连续淡化，不在提交瞬间硬切 | MUST |
| P-15 | 视点抬升（D-021）：当前身体的视点离正下方地面或水面足够高时，视界抬到对应尺度档，可以进入该档的上一档（例如高飞的鸟可进入巨岩和岛）；只扩展向上，不扩展向下；按 R 时以当时的视点重新判断 | MUST |
| P-16 | 视点抬升阈值（`scaleTiers[].viewLiftEyeHeightM`，初值 S2 3 m、S3 15 m、S4 60 m，须随档位递增）与撤销缓冲 `viewLiftHysteresis` | TUNABLE |

状态机、可见性与回滚见 [03 魂穿规格](03-possession-spec.md)。

## 移动、碰撞与镜头

| 编号 | 规则 | 等级 |
| --- | --- | --- |
| M-01 | 禁止穿模：身体、相机和魂穿落点都不能进入地形、实心实体或彼此内部；普通移动、Shift、低帧率与魂穿后都成立 | MUST |
| M-02 | 实心的大型实体（树、岩石、巨岩、岛、人、狗等）必须绕行，不能直接穿过；接触时沿表面滑开，不卡死、不弹飞 | MUST |
| M-03 | 柔性的小型实体（草）可以被其他身体经过，但必须以弯折或让开表现接触；草自身也不能钻进实心实体 | MUST |
| M-04 | 活动区：鱼在水体内，鸟在空域内且不高于上限，人可进入水域并在水面游泳，其他地面身体在陆地与浅岸，岛在海面；边界以减速、贴边或柔和回引表达，不使用死亡区（D-026） | MUST |
| M-05 | 同层的大身体（岛与岛、巨岩与巨岩）不能重叠，移动时互相绕开 | MUST |
| M-06 | 卡住时恢复到最近的有效位置；必须区分静止观察、主动顶住边界与真实卡住 | MUST |
| M-07 | 脱困时间与位移阈值、边界减速带、碰撞皮肤厚度可调 | TUNABLE |
| M-08 | 不为追求真实速度而拖慢探索；Shift 不能绕过碰撞、空域或水域限制 | MUST |
| C-01 | 默认第三人称，正常探索时能辨认当前身体的完整形态；避障迫使相机靠近时可短暂不完整，脱离障碍后平滑恢复 | MUST |
| C-02 | 相机不能穿过地形、岩石和主要资产；必要时缩短距离或调整环绕 | MUST |
| C-03 | 大目标只需显示可辨认的局部；小目标可以放大提示，但不改变实体真实比例 | MUST |
| C-04 | 过渡期间可以短暂出现目标近景；落位后在避障条件允许时恢复完整主体构图 | MUST |
| C-05 | 镜头距离、高度、FOV、灵敏度、碰撞缓冲可调；不能为了瞄准自由主动裁掉身体，避障临时靠近不属于瞄准例外 | TUNABLE |
| C-06 | 每个尺度层有自己的观察距离、雾距和运动节奏：成为草时看见整株草摇曳，成为岛时看见整岛轮廓；不能只把镜头调高调低 | MUST |

## 世界与状态

| 编号 | 规则 | 等级 |
| --- | --- | --- |
| W-01 | 主岛至少有晨雾草地、林地、山湖、岩丘、岸线与近海，群岛至少三座邻岛；地标在各尺度中位置一致 | MUST |
| W-02 | 每个身体实例有唯一 ID；魂穿只转移控制权，不复制身体；任意时刻只有一个当前主体 | MUST |
| W-03 | 干净开局固定为人（`human-first`）；关键目标与返回路径可稳定重演，不依赖随机事件 | MUST |
| W-04 | 保留会话中的位置与状态，并提供干净重开；旧原型存档不能把首版带进延后内容 | MUST |
| W-05 | 每个尺度层的典型位置至少有一个合法目标，并且总能逐级回到更小尺度（梯子完整，D-021）：每座岛从自身往下的每个尺度档都承载至少一个身体，例如每座邻岛都有巨岩、松树、海岸岩石和草；其他承载体（如岩丘）在所载最小身体与自身之间不断档。由 `validate_docs.py` 检查 | MUST |
| W-06 | 大尺度下可以不渲染小尺度细节，但位置与状态保留；岛或巨岩移动时携带其上的实体，回到小尺度后能看到变化 | MUST |
| W-07 | 世界尺寸、邻岛距离、实例密度、细节隐藏层级可调，以 M-08 的探索效率为约束 | TUNABLE |
| W-08 | 世界布局来自 `data/anchors.json`：具名个体（instances）与成片布景（scatter），个体可以放在任何承载体上（主岛、邻岛、巨岩）；增加个体或布景只改数据 | MUST |

## 界面、文字与声音

| 编号 | 规则 | 等级 |
| --- | --- | --- |
| U-01 | 极简界面；探索中右下常驻紧凑操作速查，完整说明放暂停菜单；入场镜头期间说明暂不可移动；每次有合法主目标均显示“R 成为［目标名］”，目标失效、暂停或过渡时隐藏，不因魂穿次数或存档标记停止显示；鸟鱼仅补充升降操作，不指示路线（D-024） | MUST |
| U-02 | 不显示任务列表、属性面板或长篇设定；不为 E、Space、Ctrl 显示任何提示 | MUST |
| U-03 | 世界回应采用哲学家原句，逐字引用并注明作者、出处与译本；每句不超过 18 个汉字（原创文字 8–16 字）；不是路线指令 | MUST |
| U-04 | 世界回应全局至少间隔 90 秒；随机只影响内容，不影响核心体验 | MUST |
| U-05 | 回应显示时长、淡入淡出、提示时长可调 | TUNABLE |
| A-01 | 每个类别有可辨认的音景；动物的听觉差异遵循 B-04；水下低通按实际浸没状态，鸟升高后地面声减弱 | MUST |
| A-02 | 魂穿时音景连续过渡；进入世界时默认开启环境声，游戏中随时（包括暂停时）都能开关，偏好被记住；静音不妨碍完成核心体验 | MUST |
| A-03 | 音量、滤波频率、高度衰减和交叉淡化时长可调 | TUNABLE |

## 互动

| 编号 | 规则 | 等级 |
| --- | --- | --- |
| X-01 | 互动是世界对身体的回应，用动作和声音表达：不显示文字、不计分、不给奖励，也不是任务 | MUST |
| X-02 | 互动不永久改变其他存在：受影响的存在遵守碰撞与活动区，之后回到原处；不影响玩家当前身体 | MUST |
| X-03 | 触发半径、冷却、速度、持续与返回时间可调 | TUNABLE |
| X-04 | 互动规则写在 `data/interactions.json`，用已有效果组合即可新增；新的效果类型在 `frontend/src/interactions.js` 的 `EFFECTS` 中登记，并在数据的 `effects` 中说明 | MUST |

## 资产

| 编号 | 规则 | 等级 |
| --- | --- | --- |
| L-01 | 至少一项核心可玩资产具有真实的 Lux3D 生成→修整→导入→魂穿使用的完整证据；程序化占位不能冒充 | MUST |
| L-02 | 每项资产记录来源、输入、迭代、原文件、修整、版本、用途与授权；入库前检查尺寸、轴向、材质、面数、碰撞和动作 | MUST |
| L-03 | 魂穿不等待运行时生成模型；资产缺失或加载失败时回退到已准备好的占位 | MUST |
| L-04 | 每个可魂穿种类、整片世界和每类装饰（成片草地、湖底卵石等）都有资产槽，程序化模型只是槽里的临时内容；替换资产只改 `data/entities.json` 的槽字段并运行同步脚本，不改玩法代码 | MUST |
| L-05 | 资产槽统一约定：米制，+Y 向上，-Z 朝前，原点在底部中心（岛在海平面中心），贴图内嵌；动物须提供 idle 与 move 动作，骨骼可来自 Aholo 绑骨或 Blender | MUST |
| L-06 | 面数、贴图尺寸、LOD 距离与每种的变体数量、权重预算 | TUNABLE |
| L-07 | 一个资产槽可以挂多个变体模型（`variants`，按权重分配给个体，同一个体每次加载外形不变）和远景简化模型（`lod`）；变体可以单独覆盖高度、朝向、动作和碰撞 | MUST |

资产槽的完整合同见 [06 资产槽与 Lux3D 替换](06-lux3d-asset-pipeline.md)。

## 性能、交付与维护

| 编号 | 规则 | 等级 |
| --- | --- | --- |
| F-01 | 目标设备上以 60 FPS 为目标，完整流程最低 30 FPS；记录测量环境与结果 | MUST |
| F-02 | 不允许无尽加载、卡死或无法返回；启动、加载超时和故障路径都有终点 | MUST |
| F-03 | 画质、分辨率上限、阴影、LOD 和纹理预算可调，以 F-01 为约束 | TUNABLE |
| S-01 | 提交前至少在一台非开发机上完整试玩；Demo 视频使用真实运行画面 | MUST |
| T-01 | 功能完成时同步代码、数据、文档与验收；每项 Lux3D 资产有来源记录 | MUST |
| T-02 | 每天保留一个可运行版本；截止前不加入新的核心玩法；延后需求统一登记 | MUST |

所有可调初值见 [tuning.json](../data/tuning.json) 与 [entities.json](../data/entities.json)。性能目前没有目标设备上的测量证据。

当前规则仍有待实现部分：不得把此表或 `runtimeBinding: integrated` 当作已完成证明。按 [11 实现审计](11-prototype-audit.md) 处理绑定、魂穿、音景与启动故障缺口，按 [08](08-qa-acceptance.md) 留验收证据。
